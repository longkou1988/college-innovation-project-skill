# 规则解析、交互与变更

## 1. 来源登记

为每份材料登记 source_id、文件名或URL、机构、年度、批次、发布日期（未知则null）、材料角色、适用项目类型/级别、版本、定位方式和可读取程度。网页资料需真正读取；仅有标题或旧助手概述不能视作原件已核验。用户粘贴通知可作为本次来源，注明“用户提供全文，未独立核验发布来源”。

先确认这是大创训练计划、创新创业比赛还是其他项目。不要把大创三种类型固定套给其他比赛。除非任务要求核实最新规则或引用外部研究，不为流程本身默认联网；需要最新信息时查询发布机构官方来源，注明核实日期。

逐项提取：年度、学校/组织、项目名称、当前申报级别、推荐路径、项目类型、学生年级与身份、团队人数（含不含负责人）、负责人限项、导师学历/职称与指导数量、企业导师适用条件、周期和起止日期、优先方向、禁止/重复资助条件、资助方式与额度、允许/限制科目、截止时间及时区、提交主体、材料份数及格式、评审程序、中期与结题、变更程序。未知填null并标记缺失，布尔值也不能将未知填false。

保留定位，例如“通知 三（一）2”“申报书 表1 起止年月单元格”“信息表 填表说明6”。规则摘要用“规则—原文限定—来源—对本项目的影响”四列，突出截止时间与资格风险。当前日期晚于截止时间时标明已截止，询问是在演练还是办理补报/新批次，仍可继续准备草稿，不擅改日期。

## 2. 规则效力与冲突

- 对同一适用范围，明确更正/补充条款优先于被更正旧条款。文件的上传时间不是发布日期。
- 跨年度通知建立新规则版本；明确适用的仍有效管理办法可保留，不机械抛弃，也不把旧年度缺失字段悄悄沿用。
- 通知规定“一般一年”而模板给具体起止年月，可合并记录粗粒度周期与具体实施区间；若实际不一致，标记冲突，不静默选一个。
- 校级申报后再推荐省级/国家级，记录 `application_level=校级` 与 `recommendation_path=[省级,国家级]`。学生愿望作为目标记录，不能改变入口资格。
- “原则上一、二年级”遇大三学生是需学校核实的例外条件，不能自行批准，也不把它改成绝对禁令。“最多5人”遇6人必须提示冲突。
- 两份文件适用范围不明或来源冲突，保留双方引文并询问必要的最小信息；可独立推进选题、资料整理等工作。

## 3. 必要问题

优先读取用户已给出的专业、方向、类型和模板。第一次缺通知时可说：“请提供本年度申报通知；指南、申报书模板和信息表如有也可一起提供，我先据此解析规则。”

有规则后只问未决问题，通常依次为：类型（如尚未选择）；专业/年级、团队与资源；兴趣。学校和当前级别已确定则不重复问。专业简称有多种对应时保留原称，写明候选规范名待确认，不替用户更换专业。姓名、学号等对方向推荐无关的个人信息延至填表时收集。

同一轮最多3个紧密相关问题。没有方向给5个方向并请用户选择；已有方向不强制再选方向。用户授权“你推荐最合适的并继续”时，可以说明选择理由与假设后继续，不能假定未提供的资源已存在。

## 4. 状态变更

沿用稳定ID跟踪方向D1…、选题T1…和蓝图任务W1…。记录修改内容、依据、受影响字段与时间。关系通常为：

规则/资源/项目类型 → 方向与题目可行性 → 蓝图 → 进度/成果/预算 → 表单草稿 → 审查。

模板变化 → 字段映射/字数/排版 → 草稿与审查，不重问研究兴趣。

“没有GPU”应重算算力依赖、方法、验证和预算；“改创业训练”须把目标、任务和核心成果转向用户需求/商业模式验证，保留专业与已有资源；“团队3人”应更新分工和进度而非机械删姓名；“不要AI”须移除实际AI依赖，不能只删标题词。

用户更新材料不意味着已有成果都作废；标记受影响部分为 stale，再更新。保留上一版稿件，避免覆盖用户修改。使用简单递增版本如 draft-v02；勿建立无必要的复杂数据库。
